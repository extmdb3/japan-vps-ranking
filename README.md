## 东京机房不等于中国访问快，差距在回程

这是整篇文章最该记住的一条。东京到上海物理距离两千公里左右，但如果回程走的是 Telia、Tata 或普通 NTT peering，电信骨干到东京的 RTT 可以到 150–300ms，晚高峰还会更糟。机房坐标决定下限，回程线路决定你实际感受到的速度。

所谓“三网精品回程”，具体指三条不同的骨干：

| 运营商 | 精品线路 | 说明 |
| --- | --- | --- |
| 中国电信 | CN2 GIA（AS4809） | 电信低延迟优质骨干 |
| 中国联通 | AS9929 | 联通优质骨干，区别于默认的 AS4837 |
| 中国移动 | CMIN2（AS58453） | 移动国际优化网络 |

联通那条值得多说一句。大量国际流量默认被丢到 AS4837，晚高峰拥堵是常态，9929 是另一条路。移动用户基数最大，国际路由历史口碑最差，CMIN2 就是针对这个问题的修补。三条线同时具备，才谈得上“三网都还行”，只优化其中一条的做法在实际使用中很容易翻车。

GoMami 官方文档对日本节点的延迟口径是 RTT < 50ms（中国大陆方向），并注明实际延迟受本地 ISP、时段和网络状况影响。第三方测评给出的数字更细一些：东京到华东（上海、杭州）大约 30–50ms，到华南和西部 50–80ms，并强调晚高峰能维持住。这些数字可以当作预期参考，你的实际结果取决于本地运营商。

## 常见问题

**日本云服务器需要备案吗？**
境外机房不涉及国内 ICP 备案流程。但如果域名要走国内 CDN 或接入国内服务，仍需按对应平台的要求处理。

**东京机房为什么晚上变慢？**
晚高峰国际出口拥堵。普通 transit 线路在这个时段的丢包和抖动会明显放大，走 CN2 GIA / 9929 / CMIN2 的线路受影响相对小，但不代表完全不受影响。

**24 小时退款够验证线路吗？**
够做一次针对性测试。部署 1–5 分钟完成，拿到 IP 后在中国时间晚上 8–11 点从目标用户所在地做 ping 和 traceroute，看回程是否真的走 AS4809 / 9929 / CMIN2。如果看到 AS4837 或普通 NTT 中转，直接开工单。

**能装 Windows 吗？**
Pro 和 Ultra 在购物车标注了 Windows-ready，官方系统模板包含 Windows Server 2019 / 2022。Nano / Mini / Air 只有 Linux 模板，需要 Windows 就从 Pro 起步。

**流量超了会扣钱吗？**
不会按量计费，会被限速直到下个计费周期。介意的话提前买流量包，或者直接选高一档。

**日本和香港到底差多少？**
同为 Pulse Nano，日本 $29、香港 $49，配置一样。差价买的是香港更低的物理延迟和对南方用户的覆盖。用户分布偏南就多花这 $20，偏北或用得上日本 IP 就省下来。
